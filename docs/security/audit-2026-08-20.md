# GCC Platform — Security Audit (2026-08-20)

**Auditor:** Kimi Code (automated, read-only static review)
**Scope:** `site/` (Next.js + Drizzle/Neon), `backend/` (Kotlin/Ktor scan control-plane), `composeApp/` + `shared/` (Kotlin Multiplatform), host network exposure on this box.
**Method:** read-only source review, `git ls-files`/`git grep`/`git log`, `ss -tlnp`, file-permission checks. No code was modified, no dependencies installed, no database or live endpoints touched. Secret values were never printed; only key names, file paths, and permission bits are reported.

---

## Executive summary — top 5 risks

1. **ACCOUNT TAKEOVER — unauthenticated password-set on existing passwordless accounts (HIGH, likely emergency).**
   `site/src/app/api/auth/register/route.ts:32-47`: if a worker row exists with an email but no password hash (every magic-link-created and phone-registered account), **anyone** can POST that email with a new password and is immediately issued a valid session JWT for the victim's account. No email verification, no ownership proof. Any worker who signed up via magic link is takeover-able today by email address alone.

2. **Phone verification is forgeable end-to-end (HIGH).**
   `site/src/app/api/workers/verify-phone/route.ts:55-59` issues a `registrationToken` that is **unsigned base64 JSON** (`{phone, verified: true, exp}`), and `site/src/app/api/workers/register-phone/route.ts:34-62` trusts it after only base64-decoding. Anyone can mint a token claiming any phone number is "verified" and register a worker account with `phoneVerified: true`. Additionally, the real code path has **no brute-force limit on 6-digit code guesses** (`site/src/lib/phone-verification.ts:69-99` — no attempt counter on verify), and `verify-phone` issues a full session **without checking `twoFactorEnabled`**, bypassing TOTP entirely (`verify-phone/route.ts:63-68`).

3. **No rate limiting / lockout on auth endpoints (MEDIUM-HIGH).**
   `auth/register`, `auth/login`, `auth/universal-login`, `auth/verify-2fa`, `workers/forgot-password`, `workers/request-code` (per-phone only, in-memory) have no IP- or account-level throttling. Credential stuffing, SMS/email bombing, and TOTP brute-force within the 5-minute challenge window are all unimpeded. Rate limiting that does exist (magic-link, phone-code *generation*) is an **in-memory Map on a serverless deployment**, so it resets per instance and provides little real protection.

4. **Production runs on a Next.js canary build with no HSTS/CSP (MEDIUM).**
   `site/package.json`: `next@16.3.0-canary.81`, `eslint-config-next@16.3.0-canary.81`, `drizzle-orm@1.0.0-beta.22`. Canary builds are not a stable release channel and don't receive the same security-backport guarantees. `site/vercel.json` sets `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, but **no HSTS, no Content-Security-Policy, no Permissions-Policy**; `next.config.ts` adds none either.

5. **Host network exposure beyond loopback (MEDIUM).**
   Ollama listens on `*:11434` (all interfaces — LAN `10.0.0.7/24` and Tailscale, no auth by default). An alertmanager-webhook (`~/bin/cdx-alertmanager-webhook`, pid 24019) listens on `0.0.0.0:7411`. ~25 internal services (Hermes, ComfyUI :8188, Gradio :7860, uvicorn apps, etc.) are bound to the Tailscale IP `100.67.196.13`, exposing them tailnet-wide. None of these are GCC-owned, but this box holds the GCC backend deploy dir with live R2/DB credentials, so host-level exposure is in scope.

**Good news (verified controls):** Stripe webhooks verify signatures, fail closed on a missing secret, and dedupe on event id (`api/stripe/webhooks/route.ts:59-105`). Cron endpoints fail closed when `CRON_SECRET` is unset. R2 presigned-upload keys are built from strict allowlists with `..`/traversal rejected (`site/src/lib/r2.ts:54-146`) and `scans/[id]/upload-url` checks scan ownership. Drizzle `sql` templates are parameterized throughout — **zero `sql.raw` usages**. No live secrets are committed to git. Backend docker-compose binds `127.0.0.1:8080` only, and `INDEX_SECRET` fails closed (`backend/.../Application.kt:138-141`). TOTP uses `timingSafeEqual` and recovery codes are single-use.

## Findings

| ID | Severity | Area | Location | Description | Recommended fix |
|----|----------|------|----------|-------------|-----------------|
| F-01 | **HIGH** | AuthN | `site/src/app/api/auth/register/route.ts:32-47` | Registering with the email of an existing passwordless (magic-link / phone-created) account sets a new password and returns a session JWT — no ownership proof. Full account takeover by email. | Never mutate an existing account from public register. Return 409 and force the magic-link/verify-email flow to attach a password only after proving email control. |
| F-02 | **HIGH** | AuthN | `site/src/app/api/workers/verify-phone/route.ts:55-59`; `site/src/app/api/workers/register-phone/route.ts:34-62` | `registrationToken` is unsigned base64 JSON; register-phone trusts it. Phone verification bypass — arbitrary `phoneVerified: true` accounts. | Sign the registration token (JWT/HMAC with `JWT_SECRET`) or store server-side; verify signature + binding to the phone + single use. |
| F-03 | **HIGH** | AuthN | `site/src/lib/phone-verification.ts:69-99` | No attempt counter/lockout when *verifying* a 6-digit SMS code (limit exists only on generation). ~10⁶ space, 10-min window, unlimited guesses. | Add per-phone failed-attempt counter (e.g. 5 tries → invalidate code), persist in DB/Redis, and rate-limit by IP. |
| F-04 | **MEDIUM** | AuthN (2FA) | `site/src/app/api/workers/verify-phone/route.ts:63-68` | Phone-code login issues a full worker session without consulting `twoFactorEnabled`/`totpSecret` — TOTP bypass for workers who enabled 2FA. | Mirror the password-login flow: return a 2FA challenge token when 2FA is on, complete via `/api/auth/verify-2fa`. |
| F-05 | **MEDIUM** | AuthN (2FA) | `site/src/app/api/auth/verify-2fa/route.ts:55-81` | No attempt limiting on TOTP/recovery-code guesses within the 5-minute challenge window; no lockout after failures. | Track failures per challenge/worker; invalidate challenge after N failures; alert on repeated failures. |
| F-06 | **MEDIUM** | Rate limiting | `auth/register`, `auth/login`, `auth/universal-login`, `workers/forgot-password`, `workers/request-code`; `site/src/lib/magic-link.ts:31`, `phone-verification.ts:15` | No IP/account throttling on credential and reset endpoints; existing limits are in-memory Maps, ineffective on serverless. | Shared store (Neon table/Upstash Redis) + edge middleware throttle on all `/api/auth/*` and `/api/workers/*-code` routes. |
| F-07 | **MEDIUM** | Secrets in logs | `site/src/lib/magic-link.ts:172` | When `RESEND_API_KEY` is unset, the **live magic-link token is written to logs** (`console.warn(... 'Token:', token)`). Anyone with log access gets a working login link. | Remove the token from the log line (log email only). |
| F-08 | **MEDIUM** | AuthZ model | `site/src/lib/mobile-auth.ts:18-42`; `site/src/lib/admin-auth.ts:8-28` | Admin role is baked into a 7-day JWT from a static `ADMIN_EMAILS` env list; `requireAdmin` trusts the claim with no DB re-check. Removing an admin doesn't revoke access until token expiry; role can't be revoked server-side at all. | Shorten token TTL, add a `roleVersion`/denylist check against the DB in `requireAdmin`, or move admin grants to a DB table. |
| F-09 | **MEDIUM** | Headers | `site/vercel.json`; `site/next.config.ts` | No HSTS, no CSP, no Permissions-Policy. (X-Frame-Options/nosniff/Referrer-Policy present via vercel.json.) Admin token lives in `localStorage` (`site/src/app/admin/scan-sessions/page.tsx:80-84`), so the missing CSP raises XSS→admin-token-theft impact. | Add `Strict-Transport-Security`, a baseline CSP, and move the admin token to an httpOnly cookie. |
| F-10 | **MEDIUM** | Host network | `ss -tlnp` on this box | Ollama on `*:11434` (all ifaces, unauthenticated); webhook listener on `0.0.0.0:7411`; ~25 services bound to Tailscale IP `100.67.196.13` (Hermes :8642-8662, :9119; ComfyUI :8188; Gradio :7860; uvicorn :7049/:7052/:7060/:7131; misc :8101/:8102/:8090/:7408...). LAN + tailnet attack surface on the box that stores the GCC R2/DB `.env`. | Bind Ollama to loopback (`OLLAMA_HOST=127.0.0.1`), scope 7411 to loopback, and audit which tailnet-bound services genuinely need tailnet reachability. |
| F-11 | **MEDIUM** | Dependencies | `site/package.json` | `next@16.3.0-canary.81` + `eslint-config-next@16.3.0-canary.81` (canary channel), `drizzle-orm@1.0.0-beta.22` (beta). Canary/beta channels lack stable security-backport guarantees; not checked against a CVE feed (no network scan performed). | Pin to a stable Next release line; track drizzle to a stable 1.0 when available; add `npm audit`/Dependabot in CI. |
| F-12 | **MEDIUM** | Uploads | `site/src/app/api/captures/upload-url/route.ts:50-117` | Any authenticated worker can mint presigned PUT URLs for **any** `locationCellId`/`deviceId` (no binding of `deviceId` to `auth.workerId`), enabling overwrite/poisoning of other devices' scan objects. 30-min TTL. | Bind deviceId→workerId at registration; reject mismatches; consider per-worker key prefix. |
| F-13 | **LOW** | AuthN | `site/src/app/api/auth/register/route.ts:10-18` | No password policy on register (no min length/complexity). `set-password` enforces ≥8; register enforces nothing. | Shared password policy (≥12 chars, breach-list check optional). |
| F-14 | **LOW** | Password reset | `site/src/app/api/workers/forgot-password/route.ts:38-50`; `reset-password/route.ts:35` | Reset token stored **plaintext** in `workers.resetPasswordToken` — a DB read leak yields live reset tokens. (Enumeration is correctly handled; 1h expiry.) | Store SHA-256 of the token; compare hashed. |
| F-15 | **LOW** | Session storage | `site/src/app/admin/*/page.tsx` | Web admin panel reads a 7-day admin JWT from `localStorage` — exfiltratable by any XSS. | httpOnly cookie + SameSite=strict for admin sessions. |
| F-16 | **LOW** | AuthZ | `site/src/app/api/admin/newsletter/preview/route.ts:14-28` | The only `/api/admin/*` route without `requireAdmin`. It renders placeholder data only, but it confirms the per-route guard pattern can be forgotten — there is no centralized admin guard. | Add auth anyway; better: enforce admin auth in middleware for `/api/admin/*` as defense-in-depth. |
| F-17 | **LOW** | Secrets hygiene | `site/.env.local` (mode 664), `site/.env.local.bak-20260724-premigration` (644) | Local env files with live secrets are group/world-readable. `backend/deploy/.env` and its `.bak` are 600 (good). All are untracked by git (good). | `chmod 600 site/.env.local*`; decide retention on the `.bak` files (they hold pre-migration live credentials). |
| F-18 | **LOW** | SMS design | `site/src/lib/sms-gateway.ts`; `workers/request-code/route.ts:51-58` | Verification codes are delivered via email-to-SMS carrier gateways (unreliable, and the response leaks `carrier` + `smsSent` to the client). | F-19 | **INFO** | Validation | `site/src/app/api/**` | Zod is used in only 3 of ~205 route files; the rest hand-roll validation. Coverage is generally careful, but inconsistency invites gaps (see F-01/F-02). | Adopt a shared schema-validation helper for public endpoints. |
| F-20 | **INFO** | Mobile | `composeApp/`, `shared/` | No hardcoded secrets/tokens found in app source. The R2 account id (not a secret, but an identifier) is embedded in a committed test URL (`composeApp/src/commonTest/.../RawEncodedUrlTest.kt:15`). No certificate pinning (informational only, per scope). | Optional: pin to the API domain; scrub the account id from tests. |

Acceptable for intentionally public read-only data; all other API routes send no CORS headers (default-deny). | None required; keep the wildcard off anything authenticated. |

## Quick wins (weekend-fixable)

1. **F-01** — In `auth/register`, replace the "existing && !existing.hash → set password + issue token" branch with a 409 + "use magic link to sign in, then set a password from your account" response. (~10 lines, highest impact in this report.)
2. **F-02** — Sign the phone `registrationToken` with `JWT_SECRET` (the project already uses `jose`); verify signature in `register-phone`.
3. **F-07** — Delete the token from the magic-link `console.warn`.
4. **F-03/F-05** — Add a failed-attempt counter on SMS-code and TOTP verification (even a DB column + check beats the current unlimited guessing).
5. **F-17** — `chmod 600 site/.env.local site/.env.local.bak-*`; review whether the pre-migration `.bak` files should be shredded.
6. **F-09** — Add HSTS + a starter CSP + `Permissions-Policy` to `vercel.json`.
7. **F-13** — Add a `password.length < 8` (preferably 12) check to `auth/register` to match `set-password`.
8. **F-10** — Set `OLLAMA_HOST=127.0.0.1` in the ollama systemd unit; rebind `:7411` to loopback.
9. **F-16** — Add `requireAdmin` to the newsletter preview route (one import + two lines).
10. **F-14** — Hash reset tokens before storing (store `sha256(token)`; compare hashed).

## Strategic fixes (multi-week)

- **Centralized auth-rate-limit layer** (F-06): Upstash Redis or a Neon-backed throttle table + middleware covering `/api/auth/*`, `/api/workers/request-code`, `/api/workers/forgot-password`, `/api/sponsors/forgot-password`. Replace the in-memory `Map` stores in `magic-link.ts` / `phone-verification.ts` — they are also functionally broken across serverless instances (code requested on instance A can't be verified on instance B).
- **Session/token architecture** (F-08, F-15): shorten worker JWTs from 90 days / mobile JWTs from 7 days, add refresh-token rotation, move admin grants into the DB with server-side revocation, and move web admin off `localStorage` onto httpOnly SameSite=strict cookies.
- **Unified 2FA enforcement** (F-04): make every login path (password, phone-code, magic-link, OAuth) converge on one post-auth checkpoint that honors `twoFactorEnabled`.
- **Dependency hygiene** (F-11): move off the Next canary channel to a stable line, wire `npm audit --audit-level=high` and Dependabot/Renovate into CI, and track drizzle-orm to stable.
- **Device identity for scan uploads** (F-12): register deviceIds to worker accounts; enforce the binding at presign time.
- **Tailnet segmentation** (F-10): decide which services on this box genuinely need tailnet reachability; bind everything else to loopback and front the rest with authenticated proxies (the socat forwards for Postgres/Redis are already loopback-only — keep it that way).
- **Validation standard** (F-19): adopt zod schemas for all public POST bodies via a shared `parseBody(schema)` helper.

## What was NOT verified (honest gaps)

- **No dynamic testing**: findings are from static review; no endpoint was actually called, no exploit was executed (including F-01/F-02 — high confidence from code, but not reproduced).
- **No live infrastructure checks**: R2 bucket public-access policy, Cloudflare Tunnel config, Neon roles/RLS, Stripe dashboard settings, and Vercel env values were not inspected.
- **No dependency vulnerability scan**: `npm audit` / OSV was not run (network + scope constraints); F-11 is channel-risk only, not a confirmed CVE list. `package-lock.json`/`pnpm-lock.yaml` were not diffed for typosquats.
- **Git history**: checked for tracked `.env*` files and obvious key patterns (Stripe/AWS/Slack/private-key blocks) across current files; a full historical secret scan (e.g. trufflehog over all commits) was not run.
- **iOS/macOS-specific surface**: keychain usage, ATS config, and fastlane setup were not reviewed; mobile review was a grep-level pass over `composeApp/` + `shared/` only.
- **`ss -tlnp` process attribution**: some listeners show no owning process without root; those are listed by port only.
- **`server/`, `ops/`, `scripts/`, `e2e/`, `remotion/` directories**: out of the stated scope; not reviewed.
