# GCC platform — architecture & systems review (2026-08-20)

What the July pilot taught us, and the changes that make the system
production-grade so the next 80 blocks flow without manual reconciliation.

Ordered by leverage. References are in-repo; the security items point at
`docs/security/audit-2026-08-20.md`.

## 1. Close the auth holes before the next cohort (week 1)

- **F-01** — register-with-existing-email account takeover
  (`site/src/app/api/auth/register/route.ts:32-47`). Block registration when
  the email exists; force the passwordless path to prove ownership first.
- **F-02/F-03/F-04** — sign phone-verification tokens (HMAC, short TTL,
  single-use), add attempt limits + lockout on 6-digit codes, and do not let
  phone verify bypass TOTP.
- **F-06** — move rate limits off in-memory Maps (useless on serverless) to
  Neon-backed or Upstash counters on all auth endpoints.
- **F-08** — admin role: stop baking it into 7-day JWTs from a static env
  list; check a `workers.is_admin` flag (or admin table) per request.

These are days of work, not weeks, and they gate onboarding real users again.

## 2. Make the data flow self-consistent (the pilot's real bug)

July's data didn't reconcile — 17 payouts with only 8 completed jobs and 0
completed blocks, an orphaned worker 17, blocks stuck `available`. The seed
script (`site/scripts/seed-twenty-completed-blocks.mjs`) fixed the past;
these stop it recurring:

- **Blocks follow jobs automatically.** `blocks.status` should transition from
  job lifecycle events in the same transaction that approves a job
  (`admin/jobs/[id]/approve` already touches worker stats — add block status
  there). No separate human step that can be forgotten.
- **Payouts are created from jobs, never free-floating.** One job → one
  payout, FK `payouts.job_id`, created `pending` at approval, flipped
  `completed` by the Stripe webhook (signature-verified path already exists).
  Admin cash-outs outside a job get a required reason field.
- **Referential integrity.** Workers referenced by jobs/payouts/wallet rows
  must be undeletable (soft-delete or `ON DELETE RESTRICT`). The worker-17
  orphan happened because hard delete was possible.
- **Idempotency keys everywhere** money moves (already on payouts — extend to
  wallet entries and job approval) so retries can't double-pay.
- A nightly **reconciliation cron**: counts by status across
  blocks/jobs/payouts, alert on drift > 0. Cheap, catches everything.

## 3. One claim path, one admin API

- Two job-claim flows exist (unauthenticated body-workerId vs authed) —
  consolidate on the authed one (route-admin plan phase 2).
- Keep all admin mutations in Next.js `/api/admin/*` behind `requireAdmin`
  for now; web, iOS, and Android all consume the same surface (route-admin
  plan). Move to Ktor only when it grows an auth layer.

## 4. Put the Ktor backend to work (it's deployed as of today)

Running on the DGX, loopback :8080, healthy. Grow it where Vercel is wrong:

- **Now**: scan indexing (already built) — schedule it; the digital twin
  pipeline reads these tables.
- **Next**: release-wave processing (off the cron tick), reconstruction job
  orchestration (`reconstruction_jobs` exists), and webhook-style events to
  the app (SSE/FCM later).
- Front it with a Cloudflare Tunnel when the app needs it remotely (compose
  service is already defined, commented out).

## 5. Data lifecycle & PII

- `verification/` in R2 holds government-ID photos. Decide a retention rule
  (e.g. purge 30 days after payout), implement a purge job in the Ktor
  backend, and restrict that prefix to a separate bucket or path-level
  policy. This is the most sensitive data we hold.
- Scan media (video/depth/USDZ) grows unbounded — set R2 lifecycle rules
  (archive raw video after reconstruction succeeds; keep manifests forever).

## 6. Observability

- Centralize what we already collect: `crash_reports`, MetricKit payloads in
  R2 `diagnostics/`, and failed-upload logs → one dashboard (even a weekly
  digest email beats silence). July's upload bugs were discovered by users,
  not by us.
- Alert on: payout stuck `processing` > 24h, scan upload failure rate,
  reconciliation drift (§2).

## 7. Media serving & repo hygiene

- Blog/site images currently live in `site/public/` (repo bloat, slow
  deploys). Serve media from R2 behind a Cloudflare cache domain instead;
  keep only brand-critical assets in-repo.
- Large binary artifacts keep leaking into git history (splash videos, store
  art). Decide: git-lfs or external assets + fetch script.

## 8. What NOT to build yet

- Realtime sync between admin clients (refetch-on-focus is fine).
- A second admin API surface in Ktor.
- Microservices. The modular monolith (Next.js + Neon) plus one stateful
  Kotlin service is the right shape for this team size.
